# Module 4 — Machine Learning Selection (When ML Adds Value)

> **Golden rule:** the decision question is — is the goal to generate new content, or to analyse existing data and predict/classify? Generate → generative AI. Analyse/predict/classify with a measurable target → machine learning.

## What is it?

Machine learning selection is about recognising when traditional ML — not generative AI — is the right tool. ML is suited for classification, prediction, recommendation, and anomaly detection tasks that rely on structured or labelled data, clear training examples, and measurable success metrics like accuracy, precision, or recall.

## Explain like I'm 10

Generative AI writes a new story. Machine learning looks at 1,000 old stories and tells you which ones are spam, which customer will buy next, or which transaction looks suspicious.

## Real-world analogy

Generative AI is a chef inventing a new dish. Machine learning is a food inspector who's seen thousands of dishes and can instantly tell you "this one's spoiled" or "this one will sell well" — based on patterns, not creativity.

## Example

A bank wants to know which of today's 50,000 transactions are likely fraudulent. This is anomaly detection — a classic ML use case: structured, labelled historical data, a clear "fraud/not fraud" outcome, measurable accuracy. Generative AI would be the wrong tool here — there's nothing to "create."

## How it works

**4 ML use cases:** classification, prediction, recommendation, anomaly detection. These rely on structured or labelled data, clear training examples, and measurable success metrics (accuracy, precision, recall).

**ML vs. generative AI — the core distinction:** ML predicts "what category or value?" Generative AI produces "what content should be created?"

**Business value assessment — ML delivers value when it:** automates decisions, improves prediction accuracy, detects patterns humans might miss, operates at scale in real time. Common impacts: reduced fraud, optimised operations, personalised customer experiences, data-driven forecasting.

**Decision framework:** ask — "Is the goal to generate new content or analyse existing data?" If it's classification, prediction, or pattern detection with measurable targets → machine learning is typically correct.

## When is it used?

Fraud detection, demand forecasting, spam filtering, recommendation engines, churn prediction — anywhere there's historical labelled data and a clear, measurable target.

## Key differences

ML needs structured/labelled data with a known correct answer to learn from; generative AI works well with unstructured data and doesn't need a single "correct" output. ML's output is a category or number; generative AI's output is new content. This echoes the Module 4 data types lesson: structured/labelled data → ML; unstructured/creative tasks → generative AI.

## Exam alert

**Must know:** the one decision question — "generate new content?" vs. "analyse/predict/classify existing data?" The 4 ML use case categories (classification, prediction, recommendation, anomaly detection) with example scenarios.

**Should know:** ML needs structured/labelled data + measurable success metrics (accuracy, precision, recall).

> **Exam trick:** a scenario describing fraud detection, forecasting, or spam filtering will try to tempt you toward generative AI because "AI" is in the question — but these are textbook ML tasks, not generative ones.

## Exam keywords

Classification, prediction, recommendation, anomaly detection, structured/labelled data, accuracy, precision, recall, automate decisions, pattern detection, real-time scale.

## Common confusion

People assume "AI" always means generative AI on the exam. Many scenarios (fraud detection, demand forecasting) are deliberately written to test whether you can correctly identify them as ML, not GenAI. Don't confuse recommendation (ML: suggesting from an existing catalogue based on patterns) with content generation (GenAI: creating something new that didn't exist before).

## Memory trick

> "CPRA" — Classify → Predict → Recommend → Anomaly-detect. Or: "If there's a clear right answer to learn from historical data — that's ML, not GenAI."

## Practice questions

**Question 1.** A telco wants to predict which customers are likely to cancel their subscription next month, based on 2 years of historical usage data. Is this ML or generative AI, and which use case category does it fall under?
**Answer:** Machine learning — a prediction (churn prediction) use case. There's structured/labelled historical data, a clear measurable target, and nothing new is being "created."

**Question 2.** True or false: because "AI" is in the name, any AI-related business scenario is automatically best solved with generative AI.
**Answer:** False. Scenarios like fraud detection or churn prediction are deliberately written to test whether you can correctly identify them as ML, not GenAI — "AI" in the question is a distractor, not a signal for generative AI.
